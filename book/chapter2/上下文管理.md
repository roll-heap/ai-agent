# 上下文管理与压缩

> 本文档维护第二章上下文工程在当前项目中的详细设计、技术决策、代码实现状态和待解决问题。
>
> **审计基准：** `roll-heap/ai-agent` 仓库 `master` 分支，2026-11-23。
> **事实原则：** 设计目标、已确认决策和代码实现状态分别记录。只有实际代码能够证明的能力才标记为已实现。

## 一、目标与职责边界

上下文管理负责为当前一次 Agent 执行构建满足模型上下文窗口限制的消息集合，主要工作包括：

1. 统计系统提示词、当前输入、历史消息和工具定义的 Token。
2. 计算输出预留与安全余量，得到可用于历史消息的预算。
3. 将原始消息解析为完整对话轮次，避免拆开工具调用协议。
4. 在预算不足时选择近期完整轮次，并对被排除的历史生成摘要。
5. 组装并检查本轮 AgentContext。

上下文管理不等于用户长期记忆，也不等于企业知识库。当前 Session 历史和摘要服务于会话连续性；跨会话长期记忆及企业知识检索属于第三章后续学习范围。

## 三、请求上下文构建流程

当前执行入口由 `AgentExecutor.execute()` 调用 `ContextManager.build_context()`。主要流程：

```text
AgentExecutor
    |
    v
AgentFactory 获取 AgentRuntimeConfig
    |
    v
ContextManager.build_context
    |
    +--> 校验当前输入和模型上下文配置
    +--> HistoryTurnParser 解析完整历史轮次
    +--> 统计系统提示词、工具定义、当前输入和历史消息
    +--> 计算输出预留与安全余量
    +--> 按完整轮次选择近期历史
    +--> 对被排除的历史调用 SummaryManager
    +--> 重新计算上下文，直到满足预算
    |
    v
AgentContext
    |
    v
ConversationHandler 执行 Agent
```

当前实现中，ContextManager 负责预算协调和 AgentContext 组装，没有独立的 TokenBudgetManager 或 AgentContextAssembler。

## 四、消息轮次与历史保留

### 4.1 ConversationTurn

HistoryTurnParser 将 LangChain 消息解析为完整对话轮次。用户消息开始一个新轮次，后续 AI 消息和工具结果归属当前轮次；工具调用 ID 与工具结果 ID 用于关联调用协议。

当前历史选择只使用完整轮次。未完成工具调用或不完整轮次不会被当作完整轮次参与常规选择。

### 4.2 不拆分完整轮次

**已确认的设计约束：**

- 历史选择以 ConversationTurn 为单位。
- 不做部分轮次压缩。
- 工具调用与工具结果作为完整轮次的一部分参与历史处理和摘要。
- 不单独引入 ToolResultCompressor。
- 本轮上下文选择不能覆盖或破坏 Session 中的原始历史。

原因：工具调用和工具结果之间存在协议关联，任意拆分可能使请求消息不完整；保留完整原始历史也便于后续重新构建上下文和排查问题。

### 4.3 Session 原始历史

`Session` 保存 `session_id`、完整 `history` 和 `summary_state`。`append_messages()` 只追加消息，不负责裁剪、删除或重排历史。

当前 Session 是内存对象，尚未实现跨进程持久化。

## 五、Token 统计

### 5.1 统一统计结果

`TokenCountResult` 包含：

- `total_tokens`：统计得到的 Token 数量。
- `accuracy`：EXACT 或 ESTIMATED。
- `completeness`：COMPLETE 或 INCOMPLETE。

统计结果支持累加和合并。预算判断前需要确认统计是否完整，不能把不完整结果当作可靠精确值。

### 5.2 TokenCounter 与 Provider

TokenCounter 通过注册机制发现 BaseTokenCountProvider 子类，根据 Provider 是否支持当前模型配置进行筛选，并按优先级选择 Provider。

当前代码中实际可用的 Provider 是 Hugging Face TokenizerProvider。未发现可用 Provider 时，当前实现没有通用的自动降级 Provider。

### 5.3 TokenizerProvider 当前实现

当前 Provider 使用 Hugging Face `AutoTokenizer`，并通过 Chat Template 将 LangChain 消息转换为模型输入 Token。实现包含：

- 按模型路径和 revision 缓存 Tokenizer；
- 使用锁避免并发重复加载；
- 转换 LangChain 消息和工具定义；
- 支持 AI 工具调用及其参数；
- 支持 generation prompt；
- 根据运行时兼容性标记统计准确度。

Tokenizer 加载使用本地缓存模式 `local_files_only=True`，因此运行环境需要提前具备对应 Tokenizer 文件。

### 5.4 多模态边界与历史需求

当前消息转换只支持字符串文本内容。遇到非字符串消息内容时会报错，不会静默按文本估算。

InputModality 已定义 TEXT、IMAGE、AUDIO、VIDEO，但枚举定义不代表多模态统计已经实现。当前实际能力仍是文本模式。

**历史需求记录：** 用户曾明确要求 TokenCounter 后续重写时，接口设计需要兼容 text、image 等模式；当时仅 text 模式已实现，并要求结合 OutputTokenBudgetEstimator 的逻辑。由于相关历史讨论已删除，无法恢复该方案的完整接口和细节，因此这里只保留需求约束，具体方案标记为“历史要求待补全”，不得自行补造。

## 六、预算计算与历史选择

### 6.1 预算组成

当前 ContextManager 结合以下因素计算可用输入预算：

- 模型上下文窗口 `context_window`；
- 模型配置中的 `max_output_tokens`；
- ContextBudgetConfig 的基础安全余量；
- 当 Token 统计为估算值时，按比例增加的误差补偿。

当前实现将 `max_output_tokens` 作为预算中的输出预留值，但这不代表 Agent 实际模型调用已经受到同样的生成长度限制。

### 6.2 历史选择

ContextManager 统计当前请求必要内容及候选历史，超出预算时从较早的完整历史轮次开始排除，保留较新的完整轮次。被排除的历史交给 SummaryManager 处理，随后重新构建和检查上下文。

如果系统提示词、工具定义、当前输入和现有摘要本身已经超过预算，当前流程会报错，而不是继续删除当前请求的必要内容。

### 6.3 首轮预算检查问题

**已发现的实现问题：** `ContextManager.build_context()` 在 `session.history` 为空时直接返回只包含当前输入的 AgentContext，绕过了非首轮路径中的完整预算计算和最终检查。

这属于待修复问题，不是已确认的设计目标。

## 七、摘要管理

SummaryManager 使用独立的摘要运行配置和摘要模型处理被排除的历史。摘要前会序列化完整历史消息，并检查摘要模型的输入预算，包括输入 Token、最大输出预留和安全余量。

摘要序列化需要保留消息角色语义；工具消息包含工具名称、内容和 tool_call_id。

**已确认的设计约束：**

- 摘要基于完整原始历史前缀重新生成，不采用“旧摘要 + 新增消息”的简单累加方式。
- 摘要覆盖边界以完整历史轮次数量表示。
- 新摘要覆盖范围必须从旧覆盖边界连续向后扩展。
- Session 中的原始历史保持不变。

SummaryState 保存摘要内容、covered_turn_count 和 version。更新时校验摘要非空、覆盖轮数非负且不缩小，并递增版本。

ContextManager 在摘要生成前记录版本，并在提交前检查版本是否变化。这是基础版本检查，不是完整的 revision、fingerprint 或乐观锁体系。

## 十、已知问题与后续验证

1. **首轮预算绕过：** 空历史分支直接返回，需要补充与后续轮次一致的预算检查。
2. **输出限制未贯通：** ContextManager 预留 max_output_tokens，但 Agent 初始化时没有显式将其作为模型生成参数传递。
3. **多模态未支持：** TokenizerProvider 仅处理字符串文本，需在学习和验证后扩展。
4. **Provider 缺少兜底：** 当前只有 Hugging Face Provider，未配置或不支持时没有通用自动降级。
5. **摘要上下文增长：** 摘要基于原始历史前缀重新生成，仍需持续检查摘要模型自身的输入预算。
6. **不完整轮次恢复策略：** 当前选择时仅使用完整轮次，异常末尾历史的恢复策略仍需结合会话执行流程评估。
7. **Session 未持久化：** 进程重启后不能自动恢复历史和摘要状态。
