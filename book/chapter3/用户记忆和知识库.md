# 第三章：用户记忆和知识库

## 一、学习目标与必要约束

掌握 Agent 的跨会话用户记忆、外部知识获取和知识组织能力，并理解其应用方式。

学习采用 **快速理解 → 学习技术与代码应用 → 动手运行 → 简要总结**，遵循书籍原始知识体系和顺序。以书籍原文核实概念和核心实现逻辑；区分书籍要求、项目适配和工程扩展。重点是知识点如何应用、代码如何编写；不执行书籍大规模实验或指标评测，只了解书籍报告结果，并验证当前代码的核心逻辑。

全局硬性规则见仓库根目录 [AGENTS.md](../../AGENTS.md)。本专题只维护第三章特有的路线、进度、结论和必要结果。开始或继续学习时，读取本文件及 `PROJECT_CONTEXT.md`。

## 六、关键技术结论与设计决策

- 用户经历变化时，旧经历不能继续作为当前事实；应保留历史并明确当前状态。该要求已确认，但尚未在当前数据模型和管理器中实现。
- `backstory` 只能记录来源支持的背景，不能编造人物动机、修改原因或事实时间。
- `person` 表示事实主体，`relationship` 表示主体与用户的关系。
- 创建时间、事实有效时间和事实变化时间不能混为一谈。
- Advanced JSON Cards 不等于完整历史版本审计，也不能替代原始对话证据。
- 同一业务对象的属性变化不应自动改变对象身份；具体标识算法尚未确定。
- 上述讨论结论不应描述为书籍规定的固定字段或当前代码能力。
