## 二、书籍知识路线

按照书籍第三章原始目录学习，不自行调整顺序。

### 2.1 用户记忆系统

1. 记忆能力的评估：三层次框架。
2. 记忆的层次结构：Trajectory、User Long-term Memory、Business State。
3. 用户记忆的四种存储格式：Simple Notes、Enhanced Notes、JSON Cards、Advanced JSON Cards。
4. 进阶知识表示：User as Code。
5. 用户记忆的认知科学基础：情景记忆、语义记忆、程序记忆。
6. 记忆框架案例：Mem0、Memobase。
7. 记忆压缩与整理机制。
8. 隐私保护：日志脱敏。

### 2.2 RAG 基础

1. 文档分块 Chunking。
2. 稠密嵌入 Dense Embedding。
3. 从 Word2Vec 到上下文感知表示。
4. 稀疏表示 Sparse Embedding。
5. TF-IDF 与 BM25。
6. 混合检索与重排序。

### 2.3 知识的组织与检索

1. 结构化索引：层次与关联。
2. 文件系统范式：目录结构组织知识。
3. 知识增量更新与定期整理。
4. 智能体化 RAG（Agentic RAG）。
5. 上下文感知检索（Contextual Retrieval）。
6. 从数据集中提取知识并形成结构化表示。
7. 前沿探索：多模态与参数化记忆。

以上为书籍知识路线，不代表已经完成学习或实现。每个知识点的实验和配套项目，均须在进入对应步骤时核对原文。

## 四、实验 3-2：四种记忆格式对比

### 4.1 书籍实验要求

实验目标：在统一条件下比较四种记忆格式的记忆生成、更新、检索和最终回答表现。

书籍明确要求：

1. 四种模式均提供统一的记忆生成、更新和检索接口。
2. 使用实验 3-1 的同一组 60 个用例。
3. 比较四种格式的最终回答表现。

实验 3-1 的评估方式：

- 测试集共 60 个用例，三个层次各 20 个。
- 第一层以单会话明确事实为主；第二、三层涉及跨时间、跨对象和多段会话。
- 按会话顺序生成和更新记忆。
- 后续会话处理只能访问已有记忆和新会话，不能回看之前的原始会话。
- 所有会话处理完成后，根据最终记忆和新问题生成回答。
- 使用独立评审模型（LLM-as-a-judge）对照参考答案和评分要求进行评价。

**答题模型不能直接访问原始历史会话或评审材料。** 不得将这些内容泄漏给答题模型。

书籍报告的实验 3-2 结果：Simple Notes、Enhanced Notes、JSON Cards、Advanced JSON Cards 分别通过 48、52、51、49 个用例；书中还报告了不同格式的 Token 消耗和模型调用耗时差异。这些是书籍实验结果，不是本项目实验结果。

书籍实验要求与知识点代码实践分开记录。以上 60 个用例、LLM-as-a-judge、Token 消耗和耗时数据用于说明书籍原始实验设计及报告结果，不要求本项目完整复现，也不作为当前学习验收条件。以上不代表项目已经完成完整评估。

### 4.3 已验证的关键结论

- **Simple Notes**：以独立事实保存记忆；当前检索为大小写不敏感子字符串匹配，不是语义检索。
- **Enhanced Notes**：以自然语言段落保留事实关联；单样例生成和持久化已验证，但语义相近且不包含原文关键词的问题无法命中当前检索。
- **JSON Cards**：以 `category → subcategory → key` 组织记忆；基础操作、持久化和单样例偏好使用已人工验证。当前检索仍为子字符串匹配，不具备语义检索。
- **Advanced JSON Cards**：通过 `backstory`、`person`、`relationship` 和时间戳补充事实背景与主体关系；尚无代码和实验验证。

上述状态是项目实际完成范围，不代表四种格式已在 60 个用例上完成对比。

### 4.4 重要实验限制与观察

1. Enhanced Notes 和 JSON Cards 的多轮订阅更新案例只执行了 Netflix 第一轮，出现姓名或日期提取错误；后续 Disney+、Max 和最终汇总未执行。
2. 该实验因本地 M1 16GB 设备运行 `openbmb/minicpm5-2b:2b` 耗时过长而暂停，不继续要求运行后续轮次。
3. 转账更正案例已完成理论分析，未运行模型。基础 JSON Cards 若覆盖旧值且不保留历史，无法仅凭最终值可靠还原修改过程。
4. JSON Cards 偏好使用验证覆盖了相关问题和无关问题，但仅为少量人工样例，不代表整体检索准确率。
5. 自动化测试套件尚未据此认定通过。

### 4.5 已确认的设计边界

- 用户经历变化时，旧经历不能继续作为当前事实；应保留历史并明确当前状态。
- 以上是已确认的设计要求，尚未在当前数据模型和管理器中实现。
- `backstory` 只能记录来源支持的背景，不能编造人物动机、修改原因或事实时间。
- `person` 表示事实主体，`relationship` 表示主体与用户的关系。
- 创建时间、事实有效时间和事实变化时间不能混为一谈。
- Advanced JSON Cards 不等于完整历史版本审计，也不能替代原始对话证据。
- 同一业务对象的属性变化不应自动改变对象身份；具体标识算法尚未确定。
- 以上设计理解不能描述为书籍规定的固定字段或当前代码能力。
