### 4.3 Advanced JSON Cards 实践记录

**知识目标：** 使用结构化 JSON 卡片表达用户记忆，并通过管理器维护记忆数据。

**管理器职责：** `AdvancedJsonCardMemoryManager` 负责卡片的新增、更新、删除、查询和 JSON 持久化。卡片通过 `category + card_key` 组织和定位；卡片字段承载记忆内容，`_metadata` 记录管理信息。

**独立实践技术：**

| 技术 | 用途 |
|---|---|
| OpenRouter | 提供远程模型 API |
| OpenAI Python SDK | 调用 OpenRouter Chat Completions 接口 |
| Function Calling | 让模型选择记忆管理工具并生成调用参数 |
| 自定义 ReAct 循环 | 执行工具调用，并将工具结果反馈给模型 |
| AdvancedJsonCardMemoryManager | 执行记忆卡片操作及 JSON 持久化 |

实践模型：`baidu/ernie-5.5-flash-preview:free`。模型服务和免费额度可能变化；密钥仅保存在本地配置中，不得写入项目文档或提交到 Git。

**接入工具：**

- `add_memory`：新增记忆卡片。
- `update_memory`：更新已有记忆卡片。
- `delete_memory`：删除已有记忆卡片。

**核心调用链：**

```text
用户输入
  → Agent 请求模型
  → 模型返回 tool_calls
  → Agent 解析工具名称和参数
  → Agent 调用记忆管理器
  → Agent 将工具执行结果按 tool_call_id 回传模型
  → 模型根据工具结果继续处理
  → Agent 输出最终回答
```

模型负责判断是否需要调用工具并生成参数；Agent 负责调度、执行工具和反馈结果；记忆管理器负责数据校验、实际操作及持久化。工具调用成功与否应以工具执行结果为准，不能仅凭模型发出 tool_calls 就认定操作成功。

**时间字段处理：**

- `date_created`：卡片业务字段。新增时由程序/管理器生成，不让模型猜测创建时间；更新时保留原值。
- `_metadata.created_at`：管理器记录的卡片创建元数据。
- `_metadata.updated_at`：管理器记录的最近更新时间。
- 三者语义不同，不应混用。历史数据中的错误 `date_created` 不会因修改生成逻辑而自动修复，需单独评估和处理。

**实践状态：** 用户已完成代码并确认本地测试通过。该实现属于基于书籍知识点的独立实践，不是书籍原始代码，也不代表该脚本已提交到 GitHub 分支。当前分支未检索到 `step13_openrouter_react_memory_agent.py`，因此不将其记为仓库已有源码。

## 六、关键技术结论与设计决策

- 用户经历变化时，旧经历不能继续作为当前事实；应保留历史并明确当前状态。该要求已确认，但尚未在当前数据模型和管理器中实现。
- `backstory` 只能记录来源支持的背景，不能编造人物动机、修改原因或事实时间。
- `person` 表示事实主体，`relationship` 表示主体与用户的关系。
- 创建时间、事实有效时间和事实变化时间不能混为一谈。
- Advanced JSON Cards 不等于完整历史版本审计，也不能替代原始对话证据。
- 同一业务对象的属性变化不应自动改变对象身份；具体标识算法尚未确定。
- 在 ReAct 工具循环中，模型发出工具调用请求不等于工具执行成功；Agent 必须执行工具，并将带有对应 `tool_call_id` 的执行结果反馈给模型。
- 工具参数需要在执行边界进行校验，不能只依赖模型遵循提示词或 JSON Schema。
- 新增记忆时，系统生成创建时间；更新时保留原始创建时间，避免模型生成或覆盖不可信时间。
- `date_created` 是卡片字段，`_metadata.created_at` 和 `_metadata.updated_at` 是管理器元数据，必须按各自语义使用。
- 本轮 OpenRouter + Function Calling + 自定义 ReAct 实现属于独立实践，不应表述为书籍配套代码或项目主线已集成能力。
- 上述讨论结论不应描述为书籍规定的固定字段或当前项目主线代码能力。
